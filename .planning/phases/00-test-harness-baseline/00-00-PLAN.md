## Goal

Add a minimal automated test capability (runner + scripts) and land a small set of high-signal regression tests that target the highest-risk concerns (API security + queue invariants).

## Must-haves (goal-backward)
- `npm test` runs locally and exits 0.
- At least one test file under `api/` validating `/api/proxy` behavior and one validating `/api/profile-meta` escaping/encoding.
- Tests are compatible with the repo’s ESM setup (`"type": "module"`) and pass ESLint.

## Tasks

  <name>Install and configure Vitest (ESM-compatible)</name>
  <files>
    - package.json
    - vitest.config.js
    - test/setup.js
  </files>
  <action>
    - Add devDependencies:
      - vitest

      - test: vitest run
      - test:watch: vitest

<task id="00-02">
  <name>Add API handler test harness + first security regression tests</name>
  <files>
    - test/utils/mockReqRes.js
    - api/__tests__/proxy.test.js
    - api/__tests__/profile-meta.test.js
  </files>
  <action>
    - Create `test/utils/mockReqRes.js` exporting `createMockReq` + `createMockRes` compatible with current handler patterns:
      - `res.status(code)` returns `res` for chaining
      - `res.json(obj)` and `res.send(body)` capture body
      - `res.setHeader(k,v)` captures normalized header keys
      - expose captured state via `res._state`
    - Create `api/__tests__/proxy.test.js`:
      - missing `url` query → asserts status 400 (pins expected behavior)
      - success path → stub `globalThis.fetch` to return an image buffer and assert:
        - response status 200
        - `content-type` propagated
        - response body is a Buffer
      - add `it.todo(...)` placeholders (non-failing) for Phase 1 hardening expectations:
        - blocks non-http(s) schemes
        - blocks private/loopback/link-local IP targets
        - enforces host allowlist
    - Create `api/__tests__/profile-meta.test.js`:
      - mock `@supabase/supabase-js` `createClient` to return deterministic profile data including a hostile `display_name`
      - call handler and assert returned HTML does not contain obvious injection strings (e.g., `<img`, `onerror=`, unescaped quotes in attribute contexts)
      - set expectation to the *desired* escaped/encoded output (test may initially fail until Phase 1 fixes; if so, mark it `it.todo` and add a “current behavior” test that documents existing risk)
  </action>
  <verify>
    <automated>npm test</automated>
    <automated>node -e "const fs=require('node:fs'); ['api/__tests__/proxy.test.js','api/__tests__/profile-meta.test.js'].forEach(p=>{ if(!fs.existsSync(p)) process.exit(1);});"</automated>
  </verify>
  <done>
    - API endpoints have deterministic unit tests capturing current behavior and/or desired hardening expectations.
  </done>
</task>
