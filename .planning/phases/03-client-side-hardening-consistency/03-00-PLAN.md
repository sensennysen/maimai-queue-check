<plan>
## Goal
Reduce XSS blast radius and standardize sanitizer + upload safety by enforcing consistent DOMPurify behavior across UI surfaces and validating image uploads at the service layer.

## Must-haves (goal-backward)
- No UI surface uses ad-hoc `dompurify` configuration; rendering sanitization routes through `src/utils/sanitizeHtml.js`.
- Player-name fields are sanitized as plain text (no HTML tags) before being saved.
- Profile picture and post image uploads fail fast in service-layer code when MIME type or size is invalid.
- `npm test` and `npm run lint` remain green after the changes.

## Tasks
<task id="03-01">
  <name>Standardize DOMPurify configuration (SEC-03)</name>
  <files>
    - src/utils/sanitizeHtml.js
    - src/components/profile/IntroductionCard.jsx
    - src/features/queue/components/QueueForm.jsx
    - src/features/queue/components/QueueRulesModal.jsx
    - src/__tests__/sanitizeHtml.test.js
  </files>
  <action>
    In `src/utils/sanitizeHtml.js`:
    - Keep the deterministic JSDOM + DOMPurify setup.
    - Change the export to support sanitization modes:
      - `sanitizeHtml(dirtyHtml, { mode = "rich" } = {})`
      - `mode: "rich"` uses the pinned “rich HTML” policy:
        - forbid dangerous tags: `script`, `style`, `iframe`, `object`, `embed`
        - forbid event-handler attributes: `onerror`, `onload`, `onclick`, `onmouseover`, `onfocus`, `onblur`, `onmouseenter`, `onmouseleave`, `onkeydown`, `onkeyup`, `onkeypress`
      - `mode: "text"` enforces plain text rendering by stripping all tags/attrs:
        - `ALLOWED_TAGS: []`
        - `ALLOWED_ATTR: []`

    Update rich-text/HTML surfaces to remove component-local `dompurify` usage:
    - `src/components/profile/IntroductionCard.jsx`
      - remove `import DOMPurify from 'dompurify'` and the local `sanitize()` helper
      - replace `dangerouslySetInnerHTML` content with `sanitizeHtml(introduction, { mode: "rich" })`
    - `src/features/queue/components/QueueRulesModal.jsx`
      - remove direct `DOMPurify.sanitize(...)`
      - replace with `sanitizeHtml(rules.rules, { mode: "rich" })`
    - `src/features/queue/components/QueueForm.jsx`
      - remove `import DOMPurify from 'dompurify'`
      - replace the “sanitize player names” helper with:
        - `sanitizeHtml(text.trim(), { mode: "text" })`

    Update tests in `src/__tests__/sanitizeHtml.test.js`:
    - keep existing assertions for:
      - removal of `<script>` content
      - removal of `onerror` attributes
      - neutralization of `javascript:` hrefs
    - add 1 assertion for plain-text mode:
      - `sanitizeHtml('<p>hi</p>', { mode: "text" })` does not contain `<p` and does not contain any HTML tags
  </action>
  <verify>
    <automated>npm test</automated>
  </verify>
  <done>
    - `dompurify` is only imported inside `src/utils/sanitizeHtml.js` (no longer in the three UI components).
    - Player names saved through `QueueForm` cannot contain HTML tags because `mode: "text"` strips tags.
    - Existing sanitizer tests pass, plus the new plain-text mode assertion.
  </done>
</task>

<task id="03-02">
  <name>Service-layer upload validation (SEC-04)</name>
  <files>
    - src/utils/uploadValidation.js
    - src/services/supabase/user.js
    - src/services/supabase/posts.js
    - src/__tests__/uploadValidation.test.js
  </files>
  <action>
    Create src/utils/uploadValidation.js:
    - Export:
      - `ALLOWED_IMAGE_TYPES` (same set as `src/utils/validation.js`):
        - `image/jpeg`, `image/png`, `image/gif`, `image/webp`
      - `MAX_IMAGE_SIZE_BYTES` (5MB, matching `validation.js`)
      - `validateImageUpload(file)`:
        - throws if `file` is missing `size` or `type`
        - throws if `file.size > MAX_IMAGE_SIZE_BYTES`
        - throws if `file.type` is not in `ALLOWED_IMAGE_TYPES`
        - uses consistent error messages so UI can surface them (e.g. `Unsupported file type` / `File too large`)

    Update service-layer upload methods to validate before uploading:
    - In `src/services/supabase/user.js` inside `uploadProfilePicture(userId, file)`:
      - call `validateImageUpload(file)` before computing the storage path
      - derive the extension from `file.type` (not from `file.name`), using a mapping:
        - `image/jpeg` -> `jpg`
        - `image/png` -> `png`
        - `image/gif` -> `gif`
        - `image/webp` -> `webp`
      - pass `contentType: file.type` into `supabase.storage.from(...).upload(...)`
    - In `src/services/supabase/posts.js` inside `uploadPostImage(userId, file)`:
      - call `validateImageUpload(file)` before uploading
      - derive extension from `file.type` using the same mapping
      - pass `contentType: file.type` into the storage upload options

    Add src/__tests__/uploadValidation.test.js:
    - validate that `validateImageUpload` throws for:
      - unsupported MIME type
      - a file with size just above the 5MB limit
    - validate that it does not throw for:
      - allowed MIME types under the size limit
  </action>
  <verify>
    <automated>npm test</automated>
    <automated>npm run lint</automated>
  </verify>
  <done>
    - Upload services fail fast on invalid files and never call `supabase.storage.upload(...)` when validation fails.
    - Upload requests include `contentType: file.type`.
    - All new upload validation tests pass deterministically without Supabase.
  </done>
</task>
