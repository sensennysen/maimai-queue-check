## Directory Purposes

**api/**:
- Purpose: Serverless functions for deployment platform (e.g. Vercel).
- Contains: `profile-meta.js` for generating OG/tags for public profiles.
- Key files: `api/profile-meta.js`.

**public/**:
- Purpose: Static assets bundled by Vite at build time.
- Contains: Icons, favicon, bookmarklet script if exposed, etc.
- Key files: `public/icon.png`, `public/manifest`-style assets as needed.

**src/**:
- Purpose: Core application code (React SPA).
- Contains: Components, pages, contexts, hooks, services, config, constants, utils, data, assets.
- Key files: `src/main.jsx`, `src/App.jsx`.

**supabase/**:
- Purpose: Database schema and migration scripts.
- Contains: `supabase/migrations/` with SQL migrations.

**.planning/**:
- Purpose: Project planning and codebase mapping.
- Contains: `codebase/` (STACK, ARCHITECTURE, STRUCTURE, CONVENTIONS, TESTING, CONCERNS), `research/`, milestone and phase docs.

**dist/**:
- Purpose: Compiled production build (generated).
- Contains: JS/CSS/image bundles under `dist/assets/`.
- Note: Generated output; do not add source files here.

**docs/**:
- Purpose: Documentation, images, or deployment notes.

## Naming Conventions

**Files:**
- Components in `*.jsx` with PascalCase file names: e.g. `QueueManager.jsx`, `BranchSelector.jsx`, `PublicProfilePage.jsx`.
- Hooks in `*.js` prefixed with `use`: e.g. `useQueueData.js`, `useAuth.js`, `useFeatureFlags.js`.
- Services and utilities in `*.js` with domain names: e.g. `queue.js`, `profile.js`, `validation.js`.

**Directories:**
- Feature directories use domain names (`queue`, `admin`, `songs`).
- Context directories suffixed with `Context` and `ContextDef` for definitions.
- Most directories lower-kebab-case or all lowercase.

## Where to Add New Code

**New Feature (user-facing):**
- Primary UI: create a folder under `src/features/{feature-name}/components/` for feature-specific components.
- Domain hooks: add to `src/hooks/` (e.g. `use{FeatureName}.js`) or inside `src/features/{feature-name}/hooks/` if strongly scoped.
- Data access: extend existing service modules (e.g. `src/services/supabase/{domain}.js`) or add new domain file.
- Route: add a new page component under `src/pages/` and register it in `src/App.jsx` routes.

**New Component/Module:**
- Shared component across routes: `src/components/` (choose `layout/`, `modals/`, `profile/`, or `common/` as appropriate).
- Route-level component: `src/pages/{Name}Page.jsx`.
- Context/shared state: new file in `src/contexts/` with paired `ContextDef.js` if needed, plus a custom hook in `src/hooks/`.

**Utilities:**
- Shared pure helper: `src/utils/{topic}.js`.
- Shared constants: `src/constants/{topic}.js`.
